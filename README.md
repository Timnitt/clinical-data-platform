# Clinical Data Platform

A self-guided data engineering / analytics learning project built on Synthea's
synthetic patient records. The goal is hands-on practice with Pandas and data
engineering practices, working toward FHIR R4 ingestion.

All data is **synthetic** — generated by [Synthea](https://synthetichealth.github.io/synthea/).
No real patient information is used anywhere in this repository.

## Project structure

```
clinical-data-platform/
├── data/
│   ├── raw/            # untouched Synthea CSVs (gitignored — download separately)
│   └── processed/      # cleaned/derived data written by notebooks (gitignored)
├── notebooks/
│   ├── 01_exploring_patients.ipynb      # loading, exploring, profiling patients.csv
│   └── 03_exploring_encounters.ipynb    # encounters, joins, length-of-stay
├── src/
│   └── cleaning.py     # reusable transforms, e.g. clean_patients()
├── tests/
├── requirements.txt
└── README.md
```

## Setup

```bash
python -m venv .venv

# Windows (PowerShell)
.venv\Scripts\Activate.ps1
# macOS / Linux
source .venv/bin/activate

pip install -r requirements.txt
```

## Getting the data

`data/` is gitignored, so you need to fetch the dataset yourself:

1. Download the Synthea **"100 Sample Synthetic Patient Records, CSV"** export from
   <https://synthea.mitre.org/downloads>.
2. Unzip it and place the CSVs in `data/raw/` so you have
   `data/raw/patients.csv`, `data/raw/encounters.csv`, and so on.
3. Create the output folder: `mkdir -p data/processed`

## Running the notebooks

Notebooks use paths relative to the `notebooks/` folder (`../data/raw/...`), so
run them with `notebooks/` as the working directory. Run them in order — `03`
reads the cleaned output that `01`/`02` write to `data/processed/`.

## Conventions

- Raw data is never modified in place.
- Shared transformation logic lives in `src/` as functions rather than being
  copy-pasted between notebooks. Import it with `sys.path.append("..")`.
- Dates are parsed with `pd.to_datetime(..., errors="coerce")`.
- Derived data in `data/processed/` is reproducible from `data/raw/` — it is
  never the source of truth.
